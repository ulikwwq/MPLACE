1. Purpose
Цель документа

Настоящий документ определяет бизнес-требования к платформе MPlace, описывает участников системы, их обязанности, основные бизнес-процессы и правила функционирования платформы.

Документ служит основой для проектирования функциональных требований, архитектуры, базы данных и интерфейсов.

2. Business Context

Компания-заказчик осуществляет продажу товаров на территории Кыргызской Республики.

На текущий момент основная учетная система — 1С, которая хранит данные о товарах, остатках, ценах и заказах.

Платформа MPlace становится единой точкой взаимодействия между покупателями, сотрудниками компании и внутренними бизнес-процессами.

Основная цель — автоматизировать процесс продаж и исключить ручную обработку информации.

3. Business Objectives

Проект должен обеспечить:

автоматизацию продаж;
уменьшение времени обработки заказа;
уменьшение количества ошибок;
централизованное управление товарами;
централизованное управление пользователями;
синхронизацию данных с 1С;
возможность дальнейшего масштабирования бизнеса.

6. Business Rules
BR-001

Все товары создаются в 1С либо в личном кабинете продавца (если модуль включен).

BR-002

Главным источником информации о товарах является 1С.

BR-003

Если включен модуль продавцов, продавец может управлять только своими товарами.

BR-004

Все изменения товаров журналируются.

BR-005

Удаление товара запрещено.

Используется только Soft Delete.

BR-006

Каждый заказ получает уникальный номер.

BR-007

После оформления заказа он автоматически передается в 1С.

BR-008

Изменение статуса заказа выполняется через синхронизацию с 1С.

BR-009

Все действия сотрудников записываются в Audit Log.

BR-010

Все действия пользователей записываются в Business Log.

7. User Roles
Покупатель

Может:

зарегистрироваться;
войти;
искать товары;
покупать;
просматривать историю заказов;
изменять профиль;
сохранять адреса.
Продавец

(если модуль включен)

Может:

создавать товары;
изменять товары;
управлять остатками;
видеть свои продажи;
просматривать свои заказы.
Менеджер

Может:

просматривать заказы;
менять внутренние статусы;
связываться с клиентом;
формировать документы.
Контент-менеджер

Может:

изменять описание;
менять баннеры;

Может:

Курьер

Может:

видеть свои доставки;
менять статус доставки;
подтверждать вручение.
Бухгалтер

Может:

видеть оплаты;

Может:

управлять системой;

управлять настройками;

управлять интеграциями.
Супер-администратор

Полный доступ ко всем функциям системы.

8. Business Constraints
Основная ERP — 1С.
Взаимодействие только через REST API.
Только веб-интерфейс.
Регистрация по номеру телефона.
География проекта — Кыргызская Республика.
9. Business Assumptions

Предполагается, что:

API 1С доступно;
платежные системы имеют публичные API;
SMS-провайдер поддерживает подтверждение номера;
интернет-соединение стабильно;
сотрудники используют современные браузеры.
10. Success Metrics

Проект считается успешным, если:

большинство заказов оформляется без участия оператора;
синхронизация с 1С работает автоматически;
данные каталога всегда актуальны;
роли сотрудников исключают несанкционированный доступ;
администратор управляет системой без изменения исходного кода.
11. Risks

Основные риски:

недоступность API 1С;
изменение формата API;
ошибки синхронизации;
некорректные данные в 1С;
задержки работы внешних сервисов (SMS, платежи);
человеческий фактор при управлении системой.
