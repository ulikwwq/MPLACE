1. Project Overview
Project Name

MPlace

Project Description

MPlace — это современная модульная e-commerce платформа для компаний, предназначенная для продажи любых типов товаров через веб-интерфейс с полной интеграцией с системой 1С посредством REST API.

Платформа разрабатывается как универсальное решение, которое может использоваться как одним магазином, так и сетью магазинов без изменения архитектуры.

Основной принцип проекта — максимальная гибкость, масштабируемость и независимость отдельных модулей.

2. Vision

Создать современную платформу электронной коммерции корпоративного уровня, которая:

проста для покупателей;
удобна для сотрудников компании;
легко интегрируется с внутренними системами предприятия;
выдерживает высокие нагрузки;
масштабируется без переписывания архитектуры;
поддерживает быстрое развитие функциональности.
3. Mission

Предоставить компаниям Кыргызстана надежную платформу интернет-торговли, полностью интегрированную с их внутренними бизнес-процессами и системой 1С.

4. Business Goals

Основные цели проекта:

автоматизация процесса продаж;
уменьшение ручной работы сотрудников;
единый источник информации о товарах;
автоматическая синхронизация данных с 1С;
сокращение количества ошибок;
быстрое оформление заказов;
централизованное управление всеми бизнес-процессами.
5. Product Goals

Платформа должна позволять:

публиковать каталог товаров;

синхронизировать данные с 1С;

9. Core Principles

Разработка проекта основывается на следующих принципах.

9.1 Modularity

Каждый функциональный блок является самостоятельным модулем.

9.2 Scalability

Архитектура должна позволять увеличение количества:

пользователей;
товаров;
заказов;
магазинов;
складов

без изменения архитектурных решений.

9.3 Maintainability

Любой модуль должен заменяться или расширяться без влияния на остальные части системы.

9.4 Configurability

Максимальное количество настроек управляется через административную панель.

9.5 Extensibility

Добавление нового функционала должно требовать минимальных изменений существующего кода.

9.6 Security

Безопасность учитывается на этапе проектирования.

9.7 Auditability

Любое важное действие пользователя фиксируется системой.

9.8 API First

Все функции системы реализуются через REST API.

Frontend является клиентом этого API.

11. Integration Strategy

Все внешние сервисы подключаются исключительно через адаптеры.

Прямые зависимости бизнес-логики от внешних API запрещены.

12. Storage Strategy

База данных хранит исключительно бизнес-данные.

Все медиафайлы располагаются в MinIO.

В базе сохраняются только ссылки и метаданные.

15. Success Criteria

Проект считается успешно реализованным, если:

все данные синхронизируются с 1С;
покупатель может полностью оформить заказ через сайт;
сотрудники компании могут выполнять свои задачи через административную панель;
система выдерживает промышленную эксплуатацию;
новая функциональность может добавляться без изменения базовой архитектуры.
